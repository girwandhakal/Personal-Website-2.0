What I wanted to answer before paying

A bill, an explanation of benefits (EOB), and an insurance policy can describe the same care in different formats. Even once the balance makes sense, there's still the question of what someone can afford to pay. I built ClearPath to explore both in one place.

I built the full stack, including more than 20 API routes for document handling, assistant conversations, cost estimates, financial context, and payment scenarios.

How I matched the records

Turn documents into records

After an upload, I extract the text and have the model identify whether it's an insurance plan, a bill, or an EOB. I put the result into Prisma records so the rest of the app has consistent fields to work with.

Make reconciliation inspectable

Provider names, dates, and amounts can look different across documents. I normalize them and keep the original source details and extracted notes. The app compares those fields so someone can see whether an EOB is missing or which part of a match looks wrong. They can also link records by hand.

Build the assistant’s context

When someone asks a question, I assemble the relevant insurance, document, financial, and conversation details for the model. That gives it a set of records to refer to when explaining the options.

Test affordability in the sandbox

I used Plaid's sandbox to sync test accounts and transactions and build affordability calculations. The prototype can compare costs across care settings and use the available financial context to explore payment plans.

What I tested in the prototype

I built this as a development prototype with SQLite, seeded financial personas, and sample documents. Some screens use configured or mock helpers alongside stored records. The results show what the workflow can do with test data.

I used a production build and manual API and parsing checks to verify the prototype. I'd start the automated suite with document pairs that should match and pairs that look close but have a different provider, date, or amount.

Where I'd spend more time

The working flow takes a document from upload to a linked record someone can inspect, then uses that record to explain their options.

I expected the assistant to take most of the work. The hard part was deciding when two records referred to the same thing. I'd test those matching rules independently because a convincing explanation can make a bad match harder to spot.

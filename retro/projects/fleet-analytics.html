The problem

Infrastructure devices have different ages, support status, replacement costs, and failure risks. A planner needs to see how those dimensions connect before choosing what to replace. Our Southern Company Fleet Analytics project brings those questions into one explorable dashboard.

This was a team build for UA Innovate, where it earned second place. My work included the context-aware assistant, predictive risk integration, and visualizing more than 1,000 devices on a geographic risk map.

How the dashboard is organized

Organize the planning questions

The Python and Streamlit application separates executive overview, geographic risk, lifecycle and asset health, cost and support risk, investment prioritization, and forecasting. Pandas provides the common dataset, while Plotly renders interactive views.

Connect risk with cost

This is more useful than a single risk score in isolation: a device's replacement priority can depend on where it is, whether it is supported, and what replacement would cost. The project also includes dataset upload and validation, exports, and a budget simulator for examining investment choices.

Give the assistant page context

The assistant, Southern Spark, is aware of the current dashboard page. Its context builder summarizes the dataframe into row counts, available columns, risk distribution, state counts, replacement-cost totals, and support-status counts when those fields exist. GPT-4o receives that summary with the current page name and conversation history, then streams its response.

The important tradeoff

The assistant shares context with the analysis the user is exploring, but it receives summary statistics, not unrestricted access to every device record. That keeps the payload bounded and helps it discuss dashboard-level patterns. It also means the implementation should not be described as a complete device-level retrieval system.

Forecasting and what-if analysis help explore possible risk trajectories. They do not establish that the model is production-validated for operational maintenance decisions. The case study separates a working hackathon application from a measured deployment outcome.

Result and lesson

The project earned second place at UA Innovate and connected fleet data, geographic visualization, risk forecasts, and conversational explanation in one application.

Shared context makes an assistant relevant. The practical improvement is that someone can inspect a risk view and ask a question in the same place, with the current dataset summary available to the assistant. Knowing exactly what that summary contains is as important as adding the chat interface.
